# LocGuard 的技术选择

这份说明根据当前源码整理，供阅读代码和自行撰写项目说明时参考。它不是可直接递交的人工申报正文，也不代表参赛者已理解所有实现。

## 占位符使用多重集合

`placeholders/extract` 保留每次出现的名字，然后排序。比较排序后的数组，既允许译文重排占位符，也能识别出现次数变化。

例如源文本 `{name} 赢了，祝贺 {name}` 提取为 `["name", "name"]`。只出现一次 `{name}` 的译文提取为 `["name"]`，因此不一致。普通集合会把两次出现合并成一个元素，漏掉这种问题。

名字按原样比较，`{0}` 与 `{00}` 不相同。支持 ASCII 标识符和纯数字编号，`{{` 与 `}}` 表示字面花括号。扫描器明确报告 ICU、格式说明符和不合法花括号，不把它们悄悄当成普通文本。

## CSV 为什么有四种状态

`csv/FieldState` 区分字段的四个阶段：

| 状态 | 含义 | 必须区分的情况 |
|---|---|---|
| `Start` | 字段尚未开始 | 开头的双引号可以进入引号字段，连续逗号表示空字段 |
| `Unquoted` | 未加引号的字段 | 遇到字段中的双引号应报错，不能重新进入引号模式 |
| `Quoted` | 引号内 | 逗号和换行属于内容，`""` 转义成一个双引号 |
| `Closed` | 引号已经闭合 | 后面只能是逗号、记录换行或文件结束，其他字符报错 |

如果只有“引号内/引号外”两种状态，无法区别合法的字段开头与不合法的 `abc"def`，也容易接受 `"abc"def`。四态把这些边界写在转换规则里，便于分别测试。解析器接受 LF 和 CRLF，保留引号内的换行；字段数检查由上层完成。

## 源语言错误与后续诊断

`translations.mbt` 先提取源语言占位符。源文本为空或语法错误时，记录对应问题，并把比较基准设为 `None`。其他语言仍检查空值与自身语法，但不报告占位符不匹配，因为此时没有可信的源语言基准。

这可以避免一个源文本错误引出几十条误导性的“不匹配”。源文本修复后，正常的跨语言比较会恢复。CSV 语法错误会停止本次结构检查；不合法表头停止行检查；某一行字段数不符只跳过该行，后续行继续检查。

## 物理行号与 Unicode 字符位置

CSV 的 `Row.line` 是记录开始的物理行号，从 1 开始。引号字段可以跨越多行，所以它不同于记录编号。解析器在字段内容中遇到换行也更新物理行号，CRLF 只计一次换行。

`ParseError.column` 按 Unicode 码点计数，从 1 开始，而不是 UTF-8 字节数。它不等于编辑器的屏幕列数：组合字符、宽字符和制表符可能呈现不同宽度。占位符错误消息中的 `character` 位置也是字段文本内的字符位置。语义诊断的 `Issue.column` 使用语言列名，CSV 语法诊断则把数字列位置存成字符串。

## FFI 只连接本地运行环境

`cmd/main/main.mbt` 的 JavaScript FFI 获取参数、读取文件、写入标准错误和设置退出码。文件内容使用严格 UTF-8 解码，CLI 拒绝非普通文件以及超过 16 MiB 的输入。CSV 解析、表头验证、占位符扫描、诊断组装和参数规则在 MoonBit 中实现。

这样核心库可以直接用字符串测试，文件读取失败也不会混进语义规则。当前 CLI 一次读取完整文件，属于内存解析，不是流式处理；16 MiB 限制位于 CLI，直接调用核心库的代码需要自行决定输入大小。运行过程不调用外部云服务，不上传或改写输入文件。这里没有声称未经测量的速度或内存优势。
